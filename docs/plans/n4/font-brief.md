# Plain zeros (the lead, 27 November)

**The fault:** the interface font, Atkinson Hyperlegible, draws a slashed zero. In the game "10,697" reads as "1θ,697": in every price, in the purse, in "0 of 24" and in the key cap "0". The owner called the right side "bugged"; this is a large part of it. See `mockup/zero.png` (line 1 the font as shipped, line 2 with the `tnum` feature, which is slashed too, lines 4 and 5 the prototype).

**The fix:** two derived fonts made in code from the two shipped files, in which `zero` and `zero.tf` have a plain counter, and the game uses them wherever it used Atkinson.

- Start from `docs/plans/n4/zero-prototype.py` (it works: the counter of a plain zero is the convex hull of the present counter's points). The shipped generator lives under `assets/src/` like every other generator, reads `assets/fonts/AtkinsonHyperlegible-Regular.ttf` and `-Bold.ttf`, and writes the derived files beside them. Keep the outline's curves; the counter may be a fine polygon if it is smooth from 12 to 60 pixels (look at it large), curves are better.
- **Licence:** the font is under the SIL Open Font License 1.1 (`assets/licences/AtkinsonHyperlegible-OFL.txt`), which allows modified versions under the same licence. Give the derived family its own name (not containing "Atkinson Hyperlegible"), keep the copyright notice, say in the name table's description that it is a modified version and what was changed, keep the licence fields. One ledger row per derived file (source: made in code from the two Atkinson rows; licence OFL-1.1; what was changed), and `tools/check-ledger.py` must pass.
- Other glyphs stay as they are. Check that nothing else in the font is built from the zero (a percent sign, fractions, superiors); if something is, say so in the progress file and leave it.
- The game loads the derived fonts everywhere it loaded Atkinson (start at `game/scripts/UiKit.cs`; also `tools/asset-audit/index.py`, `docs/asset-gallery/build.py`, `assets/src/2d/_fetch_fonts.sh`, the export). The two original files stay in `assets/fonts/` as the generator's source; whether they still need to ship in the game is yours to find out (do not ship what is not used).
- Digits keep their widths (the advance of `zero` and `zero.tf` does not change), so no layout may move. `game-layout` must still pass without a change to any test.
- Proof in pictures: `tools/ui-audit.sh --no-build --only=u03,u13,u22,u32 --out=build/n4/font` (after a build), and one large specimen of the digits in both weights at 15, 17, 21 and 30 pixels. Look at them yourself before you report.
